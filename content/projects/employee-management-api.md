## Overview

During my time at Andela I architected roughly 90% of this open-source REST API and its database for an employee-management platform that ended up deployed in more than 10 countries across 4 continents.

## Technical choices

**Boring, correct REST.** Predictable resource modeling, consistent error contracts and proper status codes, because an API consumed across four continents by teams you'll never meet must be self-explanatory.

**PostgreSQL schema as the source of truth.** Careful relational design (roles, departments, employment history) kept the data model honest as requirements grew.

**Built to be forked.** As an open-source project (12 stars, 5 forks), documentation and sane defaults were features, not afterthoughts.

## Related Andela work

The same period included leading a Java monolith-to-microservices migration on Docker and Kubernetes sustaining ~99.9% uptime, introducing Kafka-based asynchronous event processing, and contributing to Dev Pulse, Andela's internal engineer-performance tool.
